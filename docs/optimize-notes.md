# 资讯雷达 · 前端优化说明（2026-10-26）

本次围绕三件事：顶部更简洁、排序更智能、滚动更流畅。全部改动在原生 HTML/CSS/JS 栈内完成，未引入框架与构建。

## 1. 顶部与卡片精简

| 项 | 优化前 | 优化后 |
|---|---|---|
| 顶部结构 | 顶栏（logo+标题+更新时间+刷新）/ 提示 banner / 搜索框+来源下拉+未读收藏 chip+热榜条，共 3 层、约 160-190px | 单行顶栏（24px logo + 17px 标题 + 右侧弱化更新时间 + 刷新）+ 单行工具行（搜索 + 热榜 + 筛选），约 90px |
| 更新时间 | 顶栏第二行常驻 | 并入顶栏同行右侧 11px 灰字，下滚 60px 后淡出 |
| 来源下拉 / 未读 / 收藏 | 常驻第二行 | 收进「筛选」折叠面板，默认不占位；有激活筛选时筛选按钮变红 |
| 排序方式 | 无 | 新增「推荐排序 / 最新优先」分段控件（折叠面板内，偏好持久化） |
| 热榜入口 | AI 圈常驻一整条日/周/月按钮条 | 工具行内一个「热榜」胶囊按钮（浮层内仍可切日/周/月） |

| 卡片 | 右侧竖排 收藏/译/AI 三个按钮列 | 收藏星移到元信息行右端（26px），译/AI 收进卡片底部动作行；标签上限 3 个 |
| sticky 偏移 | `.filters { top: 57px }` 硬编码魔法数 | 顶栏实测高度写入 CSS 变量 `--topbar-h`（ResizeObserver 跟随），无 JS 时回退 52px |

## 2. 排序智能化（新增 `assets/ranking.js`）

原逻辑只按发布时间倒序 + 布尔 `hot` 分组（数据里 47% 的条目都是 hot，组内无区分度），真实热度值只存在于摘要文本里没被使用，且同一来源会连刷 20-30 条。

新打分（`smart` 模式，纯函数、可配置常量集中在 `Ranking.CFG`）：

```
score = 1.00 * 新鲜度(exp 半衰期 20h)
      + 0.90 * 热度分(0~1，对数归一化)
      + 0.35 * 来源权重(原创/技术源 > 聚合热榜)
      + 0.30 * 多源报道加成(同一事件 N 家报道)
      + 0.12 * 有正文(可 App 内阅读)
      - 0.45 * 已读降权
```

- 热度值三级回退：`item.hotScore`（抓取脚本已补写）→ 从摘要正则解析「微博热度/头条热度/抖音热度 N」（旧数据立即生效）→ `hot===true` 兜底中值。
- 打分后做**同源打散**：滑动窗口（6 条）内同一来源最多 2 条，超限顺延，保证一屏内来源多样。
- 实测（daily.json）：今天板块前 12 条覆盖 5 个来源、AI 圈前 12 条覆盖 6 个来源（优化前往往是同一来源连续十几条）。
- 「最新优先」保留原时间倒序 + 实时热点/近 24 小时/更早分组标签。

## 3. 流畅度

| 问题 | 修复 |
|---|---|
| 每张卡片都做一次全表 `filter(storyId)` → O(n²)（600 条约 36 万次，每次输入都重跑） | 数据落地时预计算 `storyCount` Map，卡片查表，复杂度降为 O(n) |
| 搜索每敲一个字就全量 `innerHTML` 重建数百张卡 | 输入防抖 150ms；按 `tab/query/source/未读/收藏/排序/数据版本` 指纹缓存筛选排序结果 |
| 一次性渲染全部卡片 | 分批渲染：首屏 30 条，滚动哨兵（IntersectionObserver，rootMargin 500px）续渲；不支持 IO 的老 WebView 回退「加载更多」按钮 |
| `applyData()` 每次同步写约 1MB localStorage（含正文），boot 阶段可能连写多次 | 缓存剥离 `content/contentSource`（体积降一个数量级）+ 延迟 1.2s 空闲写入 |
| 长列表布局与绘制开销 | `.item` 启用 `content-visibility:auto` + `contain-intrinsic-size`（渐进增强） |
| 切 tab 平滑滚动 | `scrollTo({ behavior:'instant' })` |

## 4. 数据侧（向前兼容）

- `scripts/fetch-data.mjs`：`add()` 新增 `hotScore`，微博/头条/抖音三条热榜链路写入真实热度数值；字段缺失时前端自动回退，因此**不需要立即重跑抓取**，下次 CI 抓取后自动全量生效。
- `scripts/lib/cluster.mjs`：聚类阈值放宽（中文共享 bigram `min(4,…)`→`min(3,…)`，英文词 bigram `>=3`→`>=2`）。实测当前数据集仍只有 5 个多源事件组（剩余未合并的多为「短热搜词 vs 长标题」形态，属于阈值之外的形态差异），已列入待办。
- `node scripts/selftest.mjs`：34 项通过、0 失败。

4. **聚类命中率**：目前只有约 5 个「N 家报道」组。要提升需要改聚类策略（例如对热搜短词改走「关键词包含 + 同板块 + 同时间窗」的宽松规则），但这会带来误合并风险，属于单独一轮的工作。
5. **离线缓存不再保存正文**：清除缓存后离线打开详情页会缺正文（仅显示摘要 + 原链接）。这是为了避开 1MB 同步写入的卡顿做的取舍，如不可接受可改回保留正文但延时写入。
